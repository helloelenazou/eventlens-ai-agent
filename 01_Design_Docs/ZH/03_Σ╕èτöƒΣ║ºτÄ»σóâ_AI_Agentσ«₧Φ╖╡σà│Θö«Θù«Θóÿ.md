# EventLens 2.8｜上生产环境：AI Agent 实践关键问题

> **对应题目**：基于“上市公司重大事件影响分析”场景，说明如果要上生产环境，在 AI Agent 实践方面需要考虑的关键问题。

本文件是主产品设计文档第 12 章的独立评审版。它不是泛泛讨论大模型，而是把生产问题映射到 EventLens 的机构投研场景。

## 一页结论

从 Demo 到生产，真正需要解决的不是“再加几个 Agent”，而是把以下十类问题做成**可测、可降级、可审计、可人工接管**的系统：

1. **数据与召回完整性**：多源连接器、PDF/XBRL/OCR/表格附注解析、实体主数据、独立完整性对账；
2. **Agent 编排与边界**：节点职责、schema、停止条件、工具/Token预算、失败状态；
3. **LLM 可靠性与 Verifier**：逐条引用、数字/口径确定性校验、unsupported claim 降级、Challenger；
4. **非确定性与模型版本治理**：模型/Prompt/证据快照冻结、回归集、canary、输出 diff 和回滚；
5. **重要性分诊与 NULL test**：避免所有公告都生成长报告，降低 alert fatigue；
6. **峰值容量、成本和降级**：围绕 4 月/8 月财报季 burst 设计 RPM/TPM、并发、P0 预留和人工队列；
7. **Human-in-the-loop 与 alpha 保护**：独立初判、复算痕迹、个人模型分支、AI/人工错误归因；
8. **权限、MNPI、数据许可与审计**：信息墙、动作级许可、WORM/签名留痕、法务合规放行；
9. **持续跟踪闭环**：事件 → 论点 → 跟踪项 → 新数据 → 自动比对 → 重开论点 → 复议；
10. **生产监控与持续 Eval**：召回、claim 支持、数字正确率、NULL、成本、延迟、队列、模型回归和安全降级。

## 为什么这些问题在本场景特别关键

EventLens 的用户是 15 人买方投研团队，每位研究员同时覆盖 20–30 只股票，重大事件后的有效决策窗口只有约 2–4 小时。金融场景同时具备四个特点：

- **漏一份材料可能比摘要写错一句更严重**；
- **结论必须相对事件前预期和真实持仓解释，而不是只判断新闻情绪**；
- **财报季是高并发 burst，而不是平均吞吐问题**；
- **错误输出会影响真实资金决策，因此可追溯、权限和人工复核属于产品核心，不是后台补充项**。

## 生产设计与验收矩阵

| AI Agent 生产问题 | EventLens 中的具体风险 | 生产方案 | 核心验收指标 |
|---|---|---|---|
| 数据/召回 | 漏更正、问询、债务文件 | 多源召回 + 独立目录/引用闭包对账 | 关键文档 Recall、漏检率 |
| Agent 编排 | 多 Agent 数字互相打架 | 统一事实表、结构化 schema、节点预算 | 阶段成功率、依赖可追踪率 |
| 幻觉/引用 | 引用存在但不支持结论 | claim-level verifier + 数值/口径代码校验 | citation correctness、unsupported claim rate |
| 非确定性 | 同输入输出漂移、模型升级改变判断 | 版本锁定、回归、canary、diff | 关键字段稳定率、回归失败率 |
| 分诊 | 低价值事件产生大量长报告 | P0/P1/P2/NULL/HOLD + NULL test | NULL误报/漏报、重大事件 FN |
| 峰值/成本 | 财报季几百事件同时到达 | RPM/TPM/并发预算、缓存去重、P0预留、降级 | P95延迟、排队、单事件成本 |
| 人机协作 | 自动化偏见、alpha 被抹平 | 独立初判、人工复算、个人分支 | 覆写率、重大缺陷发现率 |
| 安全合规 | MNPI、专户持仓、付费数据越权 | 服务端信息墙、动作级许可、WORM审计 | 越权测试、审计完整性 |
| 跟踪闭环 | 报告生成后假设无人验证 | tracking contract + thesis reopen | 触发准确率、复议时延 |
| 生产运营 | 数据源/模型/Prompt持续变化 | 在线监控 + 离线金标准 + 安全回退 | SLO、版本回归、降级成功率 |

## 建议的上线顺序

**Phase 1｜Shadow mode**：只读真实数据，不对外形成正式研究记录；与人工原流程并行，建立漏检和重大缺陷基线。

**Phase 2｜研究员辅助**：允许生成底稿和 Research Loop，但所有 P0/P1 结论必须人工确认；不执行买卖。

**Phase 3｜团队级生产**：接真实组合、内部模型和跟踪系统，开启信息墙、权限域、不可变审计和财报季弹性容量。

**Phase 4｜持续运营**：模型升级必须经过回归/canary；研究员覆写和事后结果持续进入评测集。

## 放行原则

生产版必须证明：

> **不漏重大事项、不制造虚假确定性、失败时能够安全降级、人工能够看见并推翻 Agent 的依据。**

因此，成功指标不能只有“生成报告更快”，还应同时覆盖研究正确性、系统可靠性、合规安全性和人机有效性。

## 双语交互层（v3.0）

同一套 EventLens Agent 支持中文与 English。用户可在顶部语言切换器中选择语言；选择结果同时控制界面、9 个 Agent 阶段名称、真实 LLM System Prompt/阶段 Prompt、最终报告与 Research Loop 后续追问。切换语言时，未修改的内置示例会自动切换为对应语言版本；用户自行输入的事件与组合上下文会保留原文，避免静默改写研究输入。

离线 Demo 为每种语言提供对应的合成案例输出；真实 LLM 模式则在请求体中传递 `language=zh|en`，后端据此选择语言专属 Prompt。语言切换不改变事实、证据、计算规则与风险控制，只改变呈现与生成语言。
