# EventLens 2.8｜生产化架构与验收边界

本文用于避免把“可运行 Demo”误称为“机构生产系统”。

## 1. 生产化必须新增的系统层

1. **数据连接器层**：交易所、公告平台、授权金融数据、公司 IR、内部研究库；支持分页、水位、版本、更正和授权回执。
2. **文档解析层**：PDF/XBRL/HTML、表格、附注、OCR、单位/期间/币种、合并范围。
3. **身份主数据层**：issuer / security / legal entity 分离，处理简称变更、借壳、A/H/ADR。
4. **召回完整性层**：独立目录对账、引用闭包、缺口状态、source health。
5. **财务计算层**：确定性计算与 LLM 叙事分离；EPS、摊薄、净债务、契约、PPA、SOTP 等由可测试代码计算。
6. **组合与权限层**：基金/专户信息墙、用户权限、真实持仓、组合聚合和风险预算。
7. **跟踪与复议层**：KPI contract、scheduler、outbox、幂等、更正历史、重开论点。
8. **审计与合规层**：不可变日志、签名、WORM、保留周期、数据许可与 MNPI 策略。
9. **模型运营层**：模型版本锁定、回归集、canary、失败降级、token/工具预算、峰值队列。

## 2. 召回验收不是“搜到几个来源”

建议冻结历史样本，按事件类型和行业标注金标准文档集合，测：

- 必需文档召回率；
- 更正/问询/债务等高影响文档漏检率；
- 重复与镜像去重准确率；
- source unavailable / partial / unknown 是否被正确区分；
- A/H/旧简称/更名是否漏召回。

## 3. LLM 运行时验收

- URL citation 与来源片段一致；
- 数值、单位、期间逐项校验；
- unsupported claim 必须降级；
- 同一冻结输入多次运行的结论差异需可监控；
- 模型版本变更必须过回归门禁；
- 高影响结论应有人审或确定性 verifier。

## 4. 重要性分诊验收

必须包含 NULL test：测试一批正确答案为“无需深挖”的公告，衡量误触发率和 alert fatigue；同时测试“资料缺失但潜在重大”的事件不能被误归 NULL。

## 5. 峰值容量验收

至少模拟：

- 450 个原始文档 / 300 个去重事件集中到达；
- 900 个原始文档 / 600 个去重事件集中到达；
- P0 与 P1 同时插队；
- API 429 / timeout / search failure；
- 研究员人工复核队列成为瓶颈。

输出不仅要有机器完成时间，还要有“研究员可完成时间”和经理审批容量。

## 6. 合规边界

当前 Demo：

- 不连接真实付费数据；
- 不处理真实 MNPI；
- 不包含真实持仓；
- 不提供法定研究记录留存；
- 不自动交易。

正式机构上线前需要合规、法务、数据供应商合同与安全团队共同批准。

## 双语交互层（v3.0）

同一套 EventLens Agent 支持中文与 English。用户可在顶部语言切换器中选择语言；选择结果同时控制界面、9 个 Agent 阶段名称、真实 LLM System Prompt/阶段 Prompt、最终报告与 Research Loop 后续追问。切换语言时，未修改的内置示例会自动切换为对应语言版本；用户自行输入的事件与组合上下文会保留原文，避免静默改写研究输入。

离线 Demo 为每种语言提供对应的合成案例输出；真实 LLM 模式则在请求体中传递 `language=zh|en`，后端据此选择语言专属 Prompt。语言切换不改变事实、证据、计算规则与风险控制，只改变呈现与生成语言。
